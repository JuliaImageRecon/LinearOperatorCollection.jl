LinearOperatorCollection.SamplingOp — Type
SamplingOp(::Type{T}; pattern, shape::Tuple=(), S = Vector{T})

builds a linear operator that samples a vector at the positions given by pattern.

Two modes are supported:

  • integer indices with shape: returns the entries of a vectorized array of size shape at the indices in pattern. A multidimensional pattern holds indices into the first dimension, one column per remaining index, and is converted with vectorizePattern. A one-dimensional pattern is used as is and not copied.
  • Boolean mask without shape: multiplies the input elementwise with a copy of pattern stored on the backend of S.

Adapt.adapt(to, op) rebuilds the operator for the storage type to from its effective pattern. Integer indices are copied and stay host arrays; the Boolean mask is copied to the target backend.

Arguments

  • pattern - integer indices or Boolean mask
  • shape::Tuple - size of the array to sample (integer indices only)
  • S - storage type of the operator

LinearOperatorCollection.RowBlockOp — Type
RowBlockOp(ops, rows; scheduler = DynamicScheduler())
RowBlockOp(ops; scheduler = DynamicScheduler())
RowBlockOp(A::AbstractMatrix, nblocks; mode = :interleaved, rng = Random.default_rng(), scheduler = DynamicScheduler())

create an operator out of the operators (or Arrays) in ops stacked vertically, [ops[1]; ops[2]; …], whose rows are scattered over the rows of the result: the rows of ops[k] are the rows rows[k] of the operator. All operators have the same number of columns, and rows is a partition of 1:nrow into index vectors or ranges, one per operator, of the length of that operator's number of rows. Without rows, the blocks are contiguous, in the order of ops.

Block-iterative solvers (e.g. ordered-subset methods) access the blocks with rowblocks. Applied as a whole, the operator multiplies every block and writes its result into its rows, and its adjoint sums the adjoints of the blocks applied to their rows. The products of the blocks run in parallel with scheduler (OhMyThreads.jl); the adjoint sums the blocks one after the other.

Blocks with contiguous rows (UnitRanges) work on views of the data; other rows are gathered into and scattered from a buffer per block (with index vectors on the device of the blocks, see Adapt.adapt). Reordering the data such that every block is contiguous avoids these copies.

The third form splits the rows of a matrix into nblocks blocks, as copies of the rows: :interleaved takes every nblocks-th row (k:nblocks:m), :contiguous consecutive rows, :random a random partition drawn with rng.

LinearOperatorCollection.GradientOp — Type

GradientOp(T::Type; shape::Tuple, dims=1:length(shape))

directional gradient operator along the dimensions dims for an array of size shape.

Required Argument

  • T - type of elements, .e.g. Float64 for ComplexF32

Required Keyword argument

  • shape::NTuple{N,Int} - shape of the array (e.g., image)

Optional Keyword argument

  • dims - dimension(s) along which the gradient is applied; default is 1:length(shape)
  • S - storage type of the operator, e.g. Vector{T} (default) or CuArray{T, 1}

Moving to another array backend

Adapt.adapt(CuArray, op)

returns a new gradient operator for the target backend, and copy(op) returns a new one with the same storage type. The target is the backing array type without element-type parameters (e.g. Array, JLArray, CuArray or ROCArray). Unlike S, which takes a parameterized type such as CuArray{T, 1}, an element-typed target such as Array{Float64} is not supported, even when its element type matches op. Adapting does not change the precision: choose T at construction. Both rebuild the operator and its temporary storage from shape and the directions taken from dims at construction; a later change of the vector passed as dims, or an iterator consumed by the construction, has no effect. op itself is not modified. The directions stay on the host. An element-typed target whose element type differs from op, such as CuArray{Float32} for a Float64 operator, throws an ArgumentError. An operator built with an S of another element type cannot be adapted to any target and throws an ArgumentError; copy keeps it as it is.

LinearOperatorCollection.RadonOp — Type
RadonOp(::Type{T}; shape::NTuple{N, Int}, angles, geometry = RadonParallelCircle(shape[1], -(shape[1]-1)÷2:(shape[1]-1)÷2), μ = nothing, S = Vector{T}) where {T, N}

Generates a RadonOp which evaluates the Radon transform operator and its adjoint (backprojection) for a given geometry and projection angles.

Arguments:

  • T - element type for the operator (e.g., Float64, ComplexF32)
  • shape::NTuple{N, Int} - size of the image
  • angles - array of projection angles
  • geometry - Radon geometry descriptor (default: parallel beam circle)
  • μ - optional attenuation map (for attenuated Radon transform)
  • S - storage type for internal vectors (default: Vector{T})

Adapt.adapt(target, op) rebuilds the operator for target with the same shape and geometry; array angles and μ are adapted to target, ranges and scalars are kept.

LinearOperatorCollection.NFFTOp — Type
NFFTOpImpl(shape::Tuple, tr::Trajectory; kargs...)
NFFTOpImpl(shape::Tuple, tr::AbstractMatrix; kargs...)

generates a NFFTOpImpl which evaluates the MRI Fourier signal encoding operator using the NFFT.

Arguments:

  • shape::NTuple{D,Int64} - size of image to encode/reconstruct
  • nodes=nothing - Array containg the trajectory nodes
  • toeplitz=false -
  • oversamplingFactor=1.25
  • kernelSize=3
  • precompute = AbstractNFFTs.TENSOR Precompute flag for the NFFT backend
  • (kargs) - additional keyword arguments for the NFFT plan
  • (cache=true) - cache a defensive copy of the node matrix and plan-constructor arguments for Adapt.adapt; this uses additional memory. Set to false to avoid that retained state and opt out of reconstruction support

LinearOperatorCollection.FFTOp — Type

FFTOp(T::Type; shape::Tuple, shift=true, unitary=true)

returns an operator which performs an FFT on Arrays of type T

Arguments:

  • T::Type - type of the array to transform
  • shape::Tuple - size of the array to transform
  • (shift=true) - if true, fftshifts are performed
  • (unitary=true) - if true, FFT is normalized such that it is unitary
  • (S = Vector{T}) - type of temporary vector, change to use on GPU
  • (kwargs...) - keyword arguments given to fft plan
  • (cache=true) - cache the FFT plan kwargs for Adapt.adapt; set to false to opt out of that reconstruction support

Adapt.adapt(target, op) preserves the shape, shift, and normalization convention, planner options, and rebuilds the plans, workspaces, and closures for target. If cache=false, adapting the operator raises an explicit ArgumentError because the planner options were not retained.
